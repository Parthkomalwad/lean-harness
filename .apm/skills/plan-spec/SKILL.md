# Plan and spec

1. Use the `brainstorming` skill. Ask one question at a time.
2. Write `docs/spec.md`: users, the one main action, scope, out of scope, data, risks.
3. Write `docs/phases.md` with the `writing-plans` skill. Each phase has a test that proves it works.
4. Mark the cuts. Put each feature that is not in the first release under "Later".
5. Gate: I approve the spec before code starts.
